Deploy CodingCON backend to Render in 5 minutes.

═══════════════════════════════════════════════════════════════════════════════
STEP 1: PREPARE RENDER ACCOUNT
═══════════════════════════════════════════════════════════════════════════════

1. Go to https://render.com
2. Sign up or log in (GitHub recommended)
3. Connect GitHub account if not already done
4. You'll see "New +" button in top right

═══════════════════════════════════════════════════════════════════════════════

1. Click "New +" → "Web Service"
2. Search for "codingCON" in your repos
3. Click "Connect" next to the repo
4. You'll see service configuration screen

  Frankfurt (closest to most users)

Branch:
  main ✓

Build Command:
  cd backend && npm install && npm run build

Start Command:

GENERATE SECRETS (REQUIRED)
═══════════════════════════════════════════════════════════════════════════════

Open PowerShell and run:

  [System.Convert]::ToBase64String([System.Text.Encoding]::UTF8.GetBytes((New-Guid).ToString()))

This gives you a random key to use for JWT_SECRET and CRON_SECRET.

Example output:
  lZk8mNoPqRsT/UvWxYz+AbCdEf1GhIjKlMnOpQrStU=

Copy 2 different keys for:
  1. JWT_SECRET
  2. CRON_SECRET

═══════════════════════════════════════════════════════════════════════════════
STEP 5: DEPLOY
═══════════════════════════════════════════════════════════════════════════════

After filling all settings:

1. Click "Create Web Service"
2. Render will:
   - Clone repo
   - Install dependencies
   - Build backend
   - Deploy

This takes 5-10 minutes.

You'll see deployment logs in real-time. Watch for:
  ✓ Build starting
  ✓ npm install complete
  ✓ npm run build complete
  ✓ Service live

═══════════════════════════════════════════════════════════════════════════════
STEP 6: VERIFY DEPLOYMENT
═══════════════════════════════════════════════════════════════════════════════

Once deployment completes:

1. You'll see a URL: https://codingcon-backend.onrender.com (or similar)
2. Go to that URL + /api/health
3. Example: https://codingcon-backend.onrender.com/api/health
4. You should see: { "status": "OK" }

If you see the status, backend is running! ✅

═══════════════════════════════════════════════════════════════════════════════
STEP 7: UPDATE FRONTEND
═══════════════════════════════════════════════════════════════════════════════

Once backend URL is confirmed:

1. Go to Vercel dashboard
2. Select codingcon-frontend project
3. Go to Settings → Environment Variables
4. Add/Update:
   Key: NEXT_PUBLIC_API_URL
   Value: https://codingcon-backend.onrender.com
5. Click "Save"
6. Go to Deployments
7. Click "Redeploy" on the latest deployment

Vercel will rebuild in ~1 minute with the new API URL.

TROUBLESHOOTING
═══════════════════════════════════════════════════════════════════════════════

Issue: Build fails
Solution:
  - Check build logs in Render
  - Ensure "cd backend &&" is in build command
  - Verify all dependencies in package.json

Issue: "MongoDB connection failed"
Solution:
  - Check MONGODB_URI is correct
  - Test URI in MongoDB Atlas connection string
  - Verify MongoDB Atlas allows Render IP (whitelist 0.0.0.0/0)

Issue: Service crashes after deploy
Solution:
  - Check logs for errors
  - Common: PORT not set (should be 4000)
  - Common: Missing environment variable
  - Check if MongoDB is reachable

Issue: CORS errors from frontend
Solution:
  - Verify CORS_ORIGIN = https://codingcon-frontend.vercel.app
  - Redeploy after changing
  - Wait 1 minute for rebuild

Issue: High memory usage (>450MB)
Solution:
  - Reduce DB_POOL_SIZE to 30
  - Reduce MAX_JUDGE_JOBS to 2
  - Upgrade to Professional plan ($25/month)

Issue: "Address already in use" error
Solution:
  - Old service still running
  - Click "Restart" in Render dashboard
  - Wait 30 seconds
  - Check logs
