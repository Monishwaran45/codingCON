WORKER PROCESS INCLUDED
═══════════════════════════════════════════════════════════════════════════════

The judge worker is now integrated into production:

How it works:
  1. User submits code
  2. Submission queued in-memory
  3. Worker picks up job
  4. Runs test cases
  5. Calculates score
  6. Updates leaderboard
  7. Notifies user via WebSocket

Development: Worker runs in same process (npm run dev)
Production: Worker runs in background (npm start)

Configuration:
  MAX_JUDGE_JOBS=4          (max jobs to run)
  QUEUE_CONCURRENCY=2       (parallel jobs)
  RABBITMQ_URL=             (empty = in-memory)
