3. Configure Service:
   
   Name:               codingcon-backend
   Environment:        Node
   Region:             Frankfurt (or closest to you)
   Branch:             main
   Build Command:      cd backend && npm install && npm run build
   Start Command:      cd backend && npm start

4. Advanced Settings → Add Environment Variables:

   NODE_ENV                   production
   PORT                       4000
   MONGODB_URI                mongodb+srv://monishlegend1780_db_user:6yBIRY2LLGfa2PLP@cluster0.juix7su.mongodb.net/codingcon?appName=Cluster0&retryWrites=true&w=majority
   JWT_SECRET                 [generate-strong-key-1]

   CLUSTER_ENABLED            true
   WORKERS                    4
   DB_POOL_SIZE               50
   DB_MIN_POOL_SIZE           10
   MAX_JUDGE_JOBS             4

TROUBLESHOOTING
═══════════════════════════════════════════════════════════════════════════════

Frontend shows "Failed to connect backend":
  ✓ Check CORS_ORIGIN in Render environment is correct
  ✓ Check NEXT_PUBLIC_API_URL in Vercel environment is correct
  ✓ Both URLs must match deployed services
  ✓ Allow 1-2 minutes for Render deployment to complete

Backend shows "MongoDB connection failed":
  ✓ Check MongoDB Atlas IP whitelist
  ✓ Add Render IP range or use 0.0.0.0/0
  ✓ Go to MongoDB Atlas → Security → Network Access

Code submissions never complete:
  ✓ Check Render logs for judge worker errors
  ✓ Verify Docker access (may not be available on all Render plans)
  ✓ Falls back to safe execution mode if Docker unavailable

Frontend slow or timing out:
  ✓ Check Vercel deployment metrics
  ✓ Might need image optimization
  ✓ Use Vercel CLI to debug: npx vercel logs
