WHY IN-MEMORY QUEUE?
═══════════════════════════════════════════════════════════════════════════════

✓ NO external dependencies (no RabbitMQ, no CloudAMQP signup)
✓ Lightning fast (memory-based, not network calls)
✓ Perfect for single-instance deployments
✓ Automatically starts job worker in the same process
✓ Works with Node.js clustering (handles 500+ users easily)

When to upgrade to RabbitMQ:
  - Need persistent job storage
  - Running multiple backend instances
  - Need job queues across machines

STEP 1: CREATE RENDER ACCOUNT & CONNECT GITHUB
═══════════════════════════════════════════════════════════════════════════════

1. Go to: https://render.com
2. Click "Sign Up" → Choose "GitHub"
3. Authorize Render to access your GitHub
4. Done!

STEP 2: GENERATE PRODUCTION SECRETS (2 MINUTES)
═══════════════════════════════════════════════════════════════════════════════

Open terminal and run these commands:

  node -e "console.log('JWT_SECRET=' + require('crypto').randomBytes(32).toString('hex'))"
  node -e "console.log('CRON_SECRET=' + require('crypto').randomBytes(32).toString('hex'))"

Save the output. You'll need these values in Step 3.

═══════════════════════════════════════════════════════════════════════════════
STEP 3: CREATE WEB SERVICE ON RENDER (5 MINUTES)
═══════════════════════════════════════════════════════════════════════════════

1. In Render dashboard, click "+ New" → "Web Service"
2. Select your GitHub repository (codingcon)
3. Fill in the form:
   
   Name:           codingcon-backend
   Region:         Frankfurt (or closest to you)
   Branch:         main
   Runtime:        Node
   Build Command:  cd backend && npm install && npm run build
   Start Command:  cd backend && npm start

4. Click "Create Web Service"
5. Wait for deployment to finish (takes 2-3 minutes)

═══════════════════════════════════════════════════════════════════════════════
TROUBLESHOOTING
═══════════════════════════════════════════════════════════════════════════════

Problem: Backend deployment fails
Solution: Check logs in Render
  - npm run build errors? Try: cd backend && npm run build
  - Missing deps? Check package.json

Problem: Frontend can't reach backend
Solution: Check CORS_ORIGIN matches Vercel URL
  - In Render Settings → Environment
  - Must be: https://your-app.vercel.app

Problem: Code submission hangs
Solution: Check backend logs
  - Render → Logs tab
  - Look for errors in job processing

Problem: "Cannot find module"
Solution: npm install in backend
  - Render: Manual re-deploy
  - Or push new commit to trigger rebuild

OPTIONAL: SCALE TO MULTIPLE BACKENDS
═══════════════════════════════════════════════════════════════════════════════

If you need more than 500 users, add RabbitMQ:

1. Sign up: https://www.cloudamqp.com/plans.html
2. Copy AMQP URL
3. Add to both backend instances:
   RABBITMQ_URL=amqp://...
4. Done! Jobs shared across instances
