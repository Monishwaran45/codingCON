HOW IT WORKS
═══════════════════════════════════════════════════════════════════════════════

Docker-based Execution:
  1. User submits code (C++, Java, Python, or JavaScript)
  2. Code stored in queue as JSON
  3. Judge worker picks up job
  4. Spins up isolated Docker container
  5. Compiles code (if needed)
  6. Runs against test cases
  7. Calculates verdict & score
  8. Updates database & leaderboard
  9. Sends WebSocket update to user

Isolation Features:
  ✓ Network disabled (--network none)
  ✓ Read-only filesystem (--read-only)
  ✓ Memory limit (256MB default)
  ✓ CPU limit (0.5 cores)
  ✓ Process limit (64 max)
  ✓ No privilege escalation
  ✓ All Linux capabilities dropped

PRODUCTION DEPLOYMENT
═══════════════════════════════════════════════════════════════════════════════

On Render:
  1. Judge worker runs as background process
  2. Docker daemon required (available on Pro plans)
  3. Falls back to native if Docker unavailable

  - No isolation (less security)
  - Still produces correct verdicts
  - Performance slightly better

VERDICT TYPES
═══════════════════════════════════════════════════════════════════════════════

AC (Accepted):
  ✓ Code compiled (if needed)
  ✓ All test cases passed
  ✓ Output matches exactly
  
WA (Wrong Answer):
  ✗ Code compiled
  ✗ Output doesn't match expected
  ✗ Verdict: Wrong Answer
  
TLE (Time Limit Exceeded):
  ✗ Code takes too long
  ✗ Exceeds JUDGE_TIMEOUT_MS
  ✗ Verdict: Time Limit Exceeded
  
MLE (Memory Limit Exceeded):
  ✗ Code uses too much memory
  ✗ Exceeds JUDGE_MEMORY_MB
  ✗ Verdict: Memory Limit Exceeded
  
RE (Runtime Error):
  ✗ Segmentation fault
  ✗ Null pointer dereference
  ✗ Division by zero
  ✗ Verdict: Runtime Error
  
CE (Compilation Error):
  ✗ Code fails to compile
  ✗ Syntax errors in C++/Java
  ✗ Verdict: Compilation Error

═══════════════════════════════════════════════════════════════════════════════
SCORING SYSTEM
═══════════════════════════════════════════════════════════════════════════════

Test Case Evaluation:
  - Each test case: Pass or Fail
  - Sample tests: 50% weight
  - Hidden tests: 50% weight
  
Points Calculation:
  - Problem: 100 points
  - If all tests AC: +100 points
  - If some tests fail: +0 points
  - No partial credit
  
Leaderboard:
  - Rank by total points (descending)
  - Tie-break by time of last submission
  
Contest Scoring:
  - Sum of all problem points
  - Updated in real-time
  - Broadcast to all users via WebSocket

TROUBLESHOOTING
═══════════════════════════════════════════════════════════════════════════════

Problem: "Compilation Error" for valid C++ code
  Solution:
    - Check for #include <iostream>
    - Verify standard headers used
    - Check for non-C++17 features
    - Use g++ -std=c++17 locally to verify

Problem: Java "Class not found" error
  Solution:
    - Class must be named same as filename (auto-fixed)
    - Remove package statements
    - Use proper main method signature
    - Ensure Scanner import: import java.util.Scanner;

Problem: "Time Limit Exceeded" for simple programs
  Solution:
    - Check for infinite loops
    - Increase JUDGE_TIMEOUT_MS if needed
    - Profile code locally to measure time
    - Optimize algorithm if possible

Problem: Wrong verdict on correct code
  Solution:
    - Check output format (trailing newlines, spaces)
    - Run code locally to verify output
    - Test with provided sample inputs
    - Check for case sensitivity

Problem: Docker not available on Render
  Solution:
    - Judge falls back to native execution
    - Less isolation but still works
    - Check Render logs for errors
    - Consider Professional plan with Docker
